# 階段 4：第一個中文字上畫面

> 執行者：cc。前置：階段 3 完成（繪字 detour 可用、`tools/strings` 可以往返）。
> 畫面若在階段 2 未取得，驗收改走「detour log 記錄到 CJK 字形繪製呼叫＋離線渲染比對」，並記「待 MG 目視」。

## 邊界
- 字型只用 OFL：Noto Sans TC／Noto Sans CJK TC。
  - 從官方 GitHub release 下載到 scratchpad 的空目錄，對照官方雜湊。
  - 字型是資料，不是程式，不執行。
- 點陣圖集由我們的腳本從字型產生，建置時生成，不 commit 二進位。授權檔與來源寫進 `README`／`assets/LICENSES`。
- 允許新增 Go 依賴 `golang.org/x/image`（opentype 光柵化）。理由：沒有它就要手寫 TrueType 光柵器。
- 中文 PATCH 檔（用 `tools/strings` 重編的 STRINGDATA）屬原文衍生物，不入版控。repo 只收翻譯表（只有我們的譯文）與建置腳本。

## 4.1 字形
- 從遊戲字型 STI 量出字高與基線（階段 3 的筆記），光柵化成同字高的 CJK 圖集。
- 第一版字表：測試字串用到的字，加上常用 500 字。格式由我們自訂，寫成具名型別。
- 測試：
  - 指定字元的圖集 bitmap 有固定雜湊；
  - 改光柵參數時，這支測試必須會紅。

## 4.2 編碼與繪製
- 依階段 3 的結論選擇路線，選擇與理由寫進 `notes/zh-patch-log.md:23`：
  - UTF-16 能一路傳到繪字層 → 直接用 Unicode code point；
  - 會被截成 8 位元 → 在字串層做雙位元組合成。
- detour 遇到 CJK 字元時，從圖集畫進遊戲的同一個緩衝區，顏色跟隨當前字色；其他字元照原路徑。
- 換行與寬度先不處理（標「已知上限」），只要求單行不溢出邊界。

## 4.3 驗收
- 挑一條主選單（或開機 30 秒內）會上畫面的字串，在翻譯表改成中文，例如「新隊伍」。產出 PATCH.002。
- 實機以 `wiz8-run.sh` 跑兩次：一次有 patch，一次無 patch（負對照）。
- 截取該區域。期望圖由同一份圖集在同位置離線渲染產生；兩者差異低於雜訊底推導的門檻（§7.3）。負對照必須高於門檻。
- 遊戲 60 秒不崩潰，目錄 diff 回到 clean。
- 「看起來對不對」由 MG 判定：截圖路徑寫進 `resume.md`「待 MG 目視」，不當 gate。

## 完成定義
1. 圖集產生器、繪製 detour 入版；測試進 CI，附四段注入。
2. 4.3 機檢通過（或依開頭的替代驗收），證據在 `notes/runs/`。
3. `resume.md` 已更新：完成項、偏離、待 MG（含目視）、下一步建議（翻譯管線、換行、字表擴充）。
4. 工作區乾淨，CI exit 0。
