# I0：玩家主手可選攻擊模式（靜態分析）

範圍：`build/wiz8.asm`、`build/Wiz8.exe`（v1.2.4）、`build/data-x/DATABASES/ITEMS.DBS`。未執行遊戲。報告不含反組譯碼與 DBS 表轉錄；常數只寫自己讀到的結論。
先講結論：**玩家沒有「從 mode 0..8 選一個」的 UI**。戰鬥指令只有兩條路徑：普通攻擊（模式由物品遮罩隨機抽）與狂暴（直接強制 mode 3）。物品遮罩之外**唯一**加入的來源是：狂暴指令（職業能力 0x14）與空手遮罩（技能 14 的有效值門檻）。

## 發現

- [已驗證] 指令分派函式依「行動型別」跳轉（型別 −1..9 共 11 項跳轉表，表在 `Wiz8.exe:0xeac58`，讀出 型別0→0x4eaaa4、型別1→0x4eaaeb）。型別 0（普通攻擊）把模式參數固定為 −1 後呼叫唯一的攻擊函式 0x53d870；型別 1 把模式參數固定為 3 後呼叫同一函式。0x53d870 全檔只有這一個呼叫點。來源：build/wiz8.asm:314764、build/wiz8.asm:314836、build/wiz8.asm:314855、build/wiz8.asm:314856。
- [已驗證] 攻擊函式 0x53d870：模式參數＝−1 才呼叫 0x542ca0 自選，否則直接使用傳入值；最後固定把結果寫入該手的 Q+5+4h。所以主手模式只有兩個入口值：自選結果、或狂暴傳入的 3。來源：build/wiz8.asm:431915、build/wiz8.asm:431919、build/wiz8.asm:431931。
- [已驗證] 行動建立函式 0x4e7cc0 的呼叫點（所見 25 處中，行動型別 0 與 1 的呼叫，如 0x596xxx 一帶）傳給模式欄（第三參數）的都是 −1；未見任何呼叫點在型別 0／1 時預先塞入 0..8 的具體模式。來源：build/wiz8.asm:548679、build/wiz8.asm:548724、build/wiz8.asm:544967、build/wiz8.asm:545073。
- [已驗證] 普通攻擊的自選函式 0x542ca0：有裝備武器的手讀物品 +0x4e 的 u16 遮罩；沒有武器的手讀手結構 H+0x31（H＝C+0x1149+0x5b·手）。之後 R(9) 抽序數 q，在遮罩 bit 0..8 上循環數 set bit，回第 q 個。遮罩為 0 時走斷言錯誤路徑。函式裡沒有任何職業、技能、等級的讀取。來源：build/wiz8.asm:438310、build/wiz8.asm:438324、build/wiz8.asm:438354、build/wiz8.asm:438376。
- [已驗證] 狂暴（mode 3）的資格函式 0x5458a0：先問 0x547940(C,0x14)（能力碼 0x14）；為假就不可用。為真再要求：至少一手的「手可用旗標」非零且 0x519ac0 回值不是 −1；最後以主手的 0x519ac0 回值 ≤1（近戰側，見 combat-2 C07 的射程<2）為結果。條件裡沒有技能值、等級、物品遮罩。來源：build/wiz8.asm:442036、build/wiz8.asm:442039、build/wiz8.asm:442080、build/wiz8.asm:442087。
- [已驗證] 能力判定 0x547940：查「當前職業的 3 項能力」(`Wiz8.exe:0x21507c`，15 職業×3 個 i32）與「種族的 5 項能力」(`Wiz8.exe:0x215130`，16 種族×5 個 i32），任一項等於查詢碼即真。我讀這兩塊 exe 位元組：能力碼 0x14 只出現在職業索引 0 的第三格；16 個種族的 5 項都沒有 0x14。故狂暴只有職業索引 0 能用。來源：build/wiz8.asm:444951、build/wiz8.asm:444962、build/wiz8.asm:444968、Wiz8.exe:0x21507c。
- [推測] 職業索引 0＝戰士（Fighter）：同一個列在索引 0 的能力為 0、0x13、0x14，與 notes/re/abilities.md:81、:102 的「Fighter 能力表」一致；本票沒有再獨立由字串表驗證職業名排序。來源：notes/re/abilities.md:81。
- [已驗證] 指令選單的按鈕顯示：選單可見性函式依 (選單,按鈕) 跳轉；第一選單的按鈕 1 呼叫 0x547940(C,0x14)（狂暴按鈕），按鈕 2 查能力 0x1c（吐息）。選單上沒有「依模式逐項列出」的結構，只有攻擊鈕與狂暴鈕。來源：build/wiz8.asm:548309、build/wiz8.asm:548312、build/wiz8.asm:548313、build/wiz8.asm:548315、build/wiz8.asm:548321。
- [已驗證] 狂暴狀態會被即時修正：每次整理行動時，若 Q+0x6d＝1（狂暴選中）而 0x5458a0 為假，就清成 0；若 Q+0x6d＝0 且「要狂暴」旗標 Q+0x104 為真而 0x5458a0 為真，就重新設為 1。行動建立函式在戰鬥中對型別 0、1、4、5 寫 Q+0x6d＝型別、Q+0x104＝(型別==1)。來源：build/wiz8.asm:391640、build/wiz8.asm:391658、build/wiz8.asm:311298、build/wiz8.asm:311386。
- [已驗證] 戰鬥中狂暴行動的合法性檢查（行動型別 1 的分支）同樣呼叫 0x5458a0，失敗則該行動不成立。來源：build/wiz8.asm:311090、build/wiz8.asm:311091、build/wiz8.asm:311244。
- [已驗證] 空手主手的遮罩 H+0x31：由 0x4ee220 在「該手沒裝備」的分支寫入；基本值 0x20（只有 bit 5＝mode 5），當武器技能 14（空手）的有效技能值（C+0x1a3+0x26·14）≥5 時改為 0x60（bit 5、6＝mode 5 與 6）。無物品時技能索引固定為 14（0x4ee285）。這是 H+0x31 的兩處寫入，我另查 `or`、`and` 形式的寫入未見其他寫入點（所見範圍內）。來源：build/wiz8.asm:319556、build/wiz8.asm:319899、build/wiz8.asm:319905、build/wiz8.asm:319909、build/wiz8.asm:319911、notes/re/formulas.md:67。
- [已驗證] 怪物不走玩家路徑：怪物行動用 0x542db0 對「怪物模板 +0xfc 的 u16 遮罩」做同一種循環挑選，結果存 +0x2e5。與玩家的 0x542ca0 是兩份獨立函式。來源：build/wiz8.asm:267003、build/wiz8.asm:267007、build/wiz8.asm:267009。
- [已驗證] ITEMS.DBS 的遮罩使用概況（只做統計，不轉錄表）：819 筆、`4+269·819` 與檔長相符；遮罩非 0 的 210 筆共 11 種不同值；各 bit 使用數 bit0＝59、bit1＝103、bit2＝51、bit3＝1、bit4＝9、bit7＝4、bit8＝38；**bit 5、bit 6 在任何物品遮罩都是 0**，所以 mode 5、6 只能來自空手遮罩。來源：build/data-x/DATABASES/ITEMS.DBS@0x4e（各記錄 +0x4e）、notes/re/combat-2.md:85。
- [已驗證] mode 3 的來源只有兩個：Bloodlust 的物品遮罩 bit 3（唯一一件，見 B16），以及戰士的狂暴指令。其餘一般武器遮罩沒有 bit 3，故「戰士能對一般武器選狂暴」來自型別 1 的強制傳入 3，不經過物品遮罩。來源：notes/re/backstab.md:37、build/wiz8.asm:314855、build/wiz8.asm:314856。
- [推測] mode 0..8 的名稱：除 mode 3＝狂暴（有指令鈕、公式有 −30／多一組骰，見 combat-2 C06、formulas.md F18）外，其餘依 HitMode／PenMode 的符號猜：mode 1 偏穿甲加成而命中降低、mode 2 反之、mode 4／7／8 在人物防禦姿態分支被特別排除（combat-2 C05）。本票沒有找到字串表或 UI 文字把 0..8 對應成名稱。來源：notes/re/combat-2.md:34、notes/re/combat-2.md:45。
- [未取得] mode 0、1、2、4、7、8 是否另有職業或技能的「解鎖」：我在 0x542ca0、0x53d870、0x5458a0、選單可見性函式裡都沒有讀到這類條件；也只有 0x5458a0 與 0x4ee220 兩處依職業／技能產生模式，但這不等於全檔不存在別處（例如存檔載入或事件腳本直接改 Q+5）。原因：本票只追玩家戰鬥指令路徑。來源：build/wiz8.asm:431931、build/wiz8.asm:438376。
- [未取得] 狂暴在雙持第二手：型別 1 的傳入值 3 只在 0x53d870 的「目前手」被使用；第二手是否再被呼叫一次、以及那次是否仍傳 3，本票沒有追呼叫迴圈（見 backstab.md B14 的結論僅限傳到當手欄）。來源：build/wiz8.asm:431915、notes/re/backstab.md:33。

## 給下一張票的規則

`MainModes(class, level, skills, item, hand)` 的文字規格（兩條指令各自一個函數）：

1. **普通攻擊（行動型別 0）**：回傳模式集合 S；實際每次開始當手攻擊時從 S 以 0x542ca0 規則（R(9) 對 S 循環）抽一個，不是選一個。
   - 手上有武器：S＝該武器物品遮罩（+0x4e）的 bit 0..8。不加職業、技能、等級項。
   - 手上沒有武器（空手）：S＝{5}；若空手技能（技能索引 14）有效值 ≥5，S＝{5,6}。
   - 抽中機率：啟用模式依 bit 序排成 m0..m(k−1)，P(mj)＝#{q∈0..8：q mod k＝j}/9（沿用 backstab.md B15）。
2. **狂暴（行動型別 1）**：資格 `Berserk(class, hands)` 為真才可用，真時模式固定＝{3}，與物品遮罩無關。
   - 資格＝職業有能力 0x14（目前只有職業索引 0，即 [推測] 戰士）且 至少一手可用且該手攻擊型別不是 −1，且 主手攻擊型別的射程回值 ≤1。與等級、技能值、種族無關。
3. 另外：物品遮罩本身帶 bit 3 的武器（原版只有 Bloodlust）即使不是戰士，普通攻擊也會抽到 mode 3；此時不經過狂暴資格。
4. 列舉角色×武器的候選集合時：對每個職業開局×武器，「普通攻擊」的 S 由物品遮罩決定；「狂暴」只對戰士類新增一列（mode 3，不依賴遮罩）。雙持時按手分開算（副手沿用 B15），主手選狂暴不傳給副手（B14）。
