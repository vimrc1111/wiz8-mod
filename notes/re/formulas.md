# Wiz8 v1.2.4 近戰公式：靜態 RE

研究日期：2026-10-08。輸入為既有 `build/wiz8.asm` 與 `build/decomp/`；版本與 sha256 前綴 `18a74ff6` 採用本票標示，沒有 exe 可重新驗證。沒有執行遊戲。比較基準為 [R11](../research/2026-10-08-R11-formulas.md)，下文以條目名稱識別。

本筆記可交接「攻擊／揮擊上限、負重、一般傷害整數運算」；完整命中率、最終 Kill 率、低等級 Lightning Strikes 尚不能直接產生精確黃金答案。`[已驗證]` 指讀過提供的 asm，非遊戲實測；欄位的語意命名另標推測，不以社群說法代替位址證據。

### 記號與證據限制

`C = *[0x685174] + 0x1862×角色索引`；`H = C+0x1149+0x5b×h`，`h=0/1` 為主／副手。`G=*[0x6836a8]`，`T=G+0x18+0xd4×角色索引`；`Q=*[0x685178]+0x106×角色索引`。物品紀錄 `I=*[0x68516c]+0x10d×物品索引`。本文的 `C+offset` 等表示該位址所存的值，型別見表。

`tz(x)` 為向零截斷，與負數的 floor 不同；`floor` 僅用於確認為非負的除法。`[條件]` 為成立時 1、否則 0。一般式假設合法角色數值、32-bit 中間值未溢位、除數非零；異常存檔不在本票範圍。`Ftoi` 是 `0x5e1c22` 所轉呼的浮點轉整數函式，捨入模式尚待 import 確認。`R(n)` 見 F01，不能無條件當成數學上的均勻骰。

**B0（每條函式的前 16 bytes 缺口）**：此份 objdump 只有解碼後的指令，未列 raw bytes；且部分跳躍表被當成指令解碼，造成下一函式入口錯位。既有 decomp 未包含以下戰鬥函式。因沒有 exe／原始區段，無法提供可核對的原始 16-byte 簽章；下文逐條標「前16 bytes：未取得（B0）」，不把重新組譯的可能編碼冒充原始 bytes。所有位址均為此 dump 的 VA。

## 發現

- **F01 隨機數的實際介面** `[已驗證]`：函式 `0x40efa0`，前16 bytes：未取得（B0）。輸入 `n`，無角色欄位；`n=0` 回傳 0。否則從 import 槽 `0x5eb1d0` 取 `r`，令 `x=low32(r×n)`、`a=high32(x×0x20005)`，回傳 `((((x-a)>>1)+a)>>14) mod n`，其中右移為 unsigned。結果範圍為 `0..n-1`。若 import 是通常的 15-bit rand，式子等價 `floor(r×n/32767) mod n`；即使假設 `r` 在 `0..32767` 均勻，輸出也非嚴格均勻，其分布為各輸出所對應的 r 個數除以 32768。import 身分、種子與跨呼叫相依性未取得。下文寫「均勻近似」的百分比，只適合近似模型；精確模型應保留此映射及 RNG 狀態。R11：沒有這層細節。來源：build/wiz8.asm:19149。

- **F02 Lightning Strikes 的入口定位與資格** `[已驗證]`：回合準備函式 `0x4e8370`（判定點 `0x4e85e5`）、消耗函式 `0x53d870`（訊息點 `0x53daf9`），前16 bytes：未取得（B0）。準備時要求 `Q+0 != 0`、`Q+1 == 0`、`feature(C,0x10)`、主手 `C+0x114e == 0`；先清 `T+0x82`，再抽籤設為 1。消耗處讀 `*[0x68c09c]+0x80c`，索引 `0x80c/4=515`，對應「的劍快如閃電！」，把這條控制流與 Lightning Strikes 連起來。技能 enum 0 命名為 Sword 是推測；`Q+1` 的完整命令語意未取得。R11「Lightning Strikes」：主手／武器限制得到具體檢查，但不能僅憑此排除所有前回合狀態影響。來源：build/wiz8.asm:312002、build/wiz8.asm:432040、translations/stringdata.json:509；字串陣列載入見 build/decomp/j.c:1。

- **F03 Lightning Strikes 發動門檻** `[已驗證]`（低等級常數 `[未取得]`）：函式 `0x4e8370`、`0x5479b0`，前16 bytes：未取得（B0）。輸入為當前職業 `p=C+0x69` 與該職業等級 `L=C+0x8d+4p`。令 `scale(L,f)=f`（unsigned `L>20`），否則 `scale(L,f)=(2L+A)×f×B`，`A=float[0x5ee800]`、`B=float[0x5ed490]` 未附在 dump。門檻 `t=uint8(Ftoi(scale(L,12.0)))`，發動條件 `R(100)<t`。**L≥21 的門檻確定為 12；均勻近似發動率 12%**。`0x5479b0` 沒有使用傳入的 feature id，而是直接依當前職業等級縮放。此抽籤式沒有讀 STR、DEX、SPD、技能值或負重；裝備與狀態會影響 F02/F04 資格。R11：沒有公開的機率式；不可把總等級或 Sword 技能代入 L。來源：build/wiz8.asm:312021、build/wiz8.asm:445001。

- **F04 Lightning Strikes 額外揮擊與主手限制** `[已驗證]`：函式 `0x53d870`，前16 bytes：未取得（B0）。當 `T+0x82!=0` 且 `h=0`，再次要求 `C+0x114e=0`、`C+0xa15=0`，增加 `3+[R(11)+L≥20]` 到本次剩餘揮擊數 `T+0x68`，然後清除旗標；主手的後兩個条件失敗亦清除，副手不消耗。因此增加的是 **3 或 4 揮**，不是額外 3–5 個完整 attack；`L≥20` 固定加 4，`L≤9` 固定加 3，`10≤L≤19` 的加 4 機率在均勻近似下為 `(L-9)/11`。這是回合準備抽籤、後續一次主手消耗，不是每揮重新抽籤。`C+0xa15` 狀態名稱未取得；追加數不保證在目標死亡／行動中斷時全部打出。R11「Lightning Strikes 額外攻擊數／副手」：+3–5 不同；主手限定相同。來源：build/wiz8.asm:432040。

- **F05 特性資格查表** `[已驗證]`（職業名稱映射 `[未取得]`）：函式 `0x547940`，前16 bytes：未取得（B0）。`feature(C,k)` 檢查當前職業 `C+0x69` 對應 `0x61507c+12p` 的 3 個項目，以及種族 `C+0x71` 對應 `0x615130+20r` 的 5 個項目；另有 feature `0x1c` 的 `C+0xa79` 特例。這說明資格並非單純「曾經有該職業等級」；資料表缺失，不能列出所有享有 Lightning Strikes／背刺／忍者被動的職業與種族。R11「職業特殊能力」：補出取得資格與等級倍率是兩個分開步驟。來源：build/wiz8.asm:444951。

- **F07 合成技能 K 與雙持修正 M** `[已驗證]`：函式 `0x4ee220`，前16 bytes：未取得（B0）。技能值 `skill(j)=C+0x1a3+0x26j`；`W=skill(H+5)`、`B=skill(H+9)`、`D=skill(18)=C+0x44f`。先令 `u=floor(2(B+2W)/3)`、`d=20`；若另一手 `H_other+0=1` 且 `H_other+4!=0`，加 `floor(W_other/2)` 到 u 並令 d=25；若 `C+0x12b5!=0`，再加 D 到 u、加 10 到 d。`K=floor(10u/d)` 存入 `H+0xd`。雙持旗標由兩手 type=1 且 enabled 設定；雙持時 `M=-10-tz((100-D)/4)`（主手）、`-20-tz((100-D)/4)`（副手），否則 M=0。R11「雙持」：M 使用 **Dual Weapons 技能 D**，不是該手 Weapon 技能；保留每一步整數截斷。來源：build/wiz8.asm:319654、build/wiz8.asm:319673、build/wiz8.asm:319729。

## 規格疑慮

1. **前 16 bytes 無法交付原始簽章**：輸入 asm 不含 raw bytes，沒有 exe，也不准啟動 RE 流程；因此依允許的 `[未取得]` 格式列 B0。請 cc 提供上述函式各 16 bytes 的 dump。`0x4ee130`、`0x541c00` 尤須按呼叫目標重新反組譯，現有線性輸出入口錯位。機檢只檢查來源與三態標記，不會驗證簽章或公式正確性，通過不能視為證據缺口已補齊。
