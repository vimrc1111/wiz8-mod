# X1 即時怪物位置（靜態研究）

> 對象：`build/Wiz8.exe`（PE32）；行號＝`build/wiz8.asm` 行（格式 `  ADDR:\tinsn`）。VA→檔案位移＝VA−0x400000。
> 證據方式：全部 `static_analysis`（只讀反組譯，沒跑遊戲）。每條標 [已驗證]／[推測]／[未取得]；[已驗證] 僅指「反組譯所見指令確實如此」，不是執行期驗證。
> 資料位址（0x65xxxx–0x68xxxx）在 exe 檔內是 bss／零，檔案位移處讀到的 16 bytes 不含意義，所以資料位址不附 bytes；程式位址附 `build/Wiz8.exe@` 位移與前 16 bytes。
> 產生指令：`grep -n` 對 wiz8.asm 找呼叫者／引用，`sed -n` 讀行範圍，`xxd -s <VA-0x400000> -l 16 -p build/Wiz8.exe` 取 bytes。

## 結論（先講）

- 怪物容器＝兩層：「群組」G 向量與「個體」E 向量；個體 E 的 +0xc 指向模型物件 M；M 內有世界座標。
- 每幀可讀的路徑（靜態推得，待執行期傾印確認）：遍歷 `*(u32*)0x683fad` 與 `*(u32*)0x683fb9` 兩個向量的元素 E，取 `M = *(u32*)(E+0xc)`，M 非 0 時讀 `float M+0x118/+0x11c/+0x120`（X／Y／Z）。
- 座標與隊伍同一個 getter、同一個類別（見 X1-Q2），單位與軸相同（X、Z 為水平面）。

## X1-Q1 容器

- [已驗證] 四個向量指標全域（未對齊 dword，緊接戰鬥旗標 0x683f94 之後）：`0x683fad`＝個體向量 A；`0x683fb1`＝群組向量 A；`0x683fb9`＝個體向量 B；`0x683fbd`＝群組向量 B。建立於 `0x4e3720`（asm 305275 起；`build/Wiz8.exe@0xe3720`：b801000000a3be746800a3ba74680083）。該函式開頭把 id 計數器 `0x6874be`（個體）與 `0x6874ba`（群組）重設為 1。
- [已驗證] 向量物件：資料指標在 +0；元素數在 +8。`0x5e2c70`（size，`@0x1e2c70`：8b44240485c07501c38b4008c3909090，asm 654256）回傳 [v+8]；`0x5e2870`（get(v,idx)，`@0x1e2870`：8b44240485c0740f8b4c24083b48087d，asm 約 654090）idx≥count 回 0，否則回 [[v]+idx*4]；`0x5e2480` push_back；`0x5e2890` 找索引（不在回 −1）；`0x5e27c0` 依 id 移除。
- [已驗證] 個體依 id 取：`0x4e5620(id)`（`@0xe5620`：53568b74240c81fe1027000057727581，asm 307890–307956）：id 在 [0x2710,0x4e20) 取 `0x683fb9[id-0x2710]`，其餘取 `0x683fad[id]`；找不到寫錯誤 log。`0x4e5550(id,flag)`（`@0xe5550`：a1ad3f680056575033f6e811d70f008b，asm 307807–307885）依 E+0 比對 id，先掃 0x683fad 再掃 0x683fb9，回索引（B 向量加 0x2710）或 −1。emu.md:65 也是用這兩個函式。
- [已驗證] 個體 E 建立：`0x4e3930(G, D, pos)`（`@0xe3930`：535556576825040000ff15a0b15e008b，asm 305446 起）配 0x425 bytes、清零；E+0x0＝全域計數 `0x6874be` 遞增（不為 0）；E+0x4＝G+0x0（群組 id）；E+0x8＝G+0x18（樣板 id）；E+0x16＝G 的 +0x2a byte；E+0x17..0x22＝pos 指標指向的 3 個 float（見 Q2）；E+0xc（M 指標）、E+0x10、E+0x14、E+0x15 初始 0；E+0x24f＝−1.0f。推入哪個向量由樣板 D 的 byte `D+0x26a` 決定：非 0 推入 `0x683fb9`（指令 `@0xe3a7c`：a1b93f680050eb078b0dad3f680051e8，asm 305551），0 推入 `0x683fad`（asm 305552–305557）。
- [已驗證] 群組 G 建立：`0x50f1a0(templateId, pos, flag, …)`（`@0x10f1a0`：8b4c2408b8090000003bc87604894424，asm 366296 起）配 0x12b bytes；G+0x0＝全域計數 `0x6874ba`；G+0x4＝成員數；G+0x8＝成員 id 向量；G+0x18＝樣板 id；G+0x1c/+0x20/+0x24＝pos 的 3 個 float（見 Q6）。同樣由 `D+0x26a` 決定推入 `0x683fbd`（非 0）或 `0x683fb1`（0）（指令 `@0x10f2bc`：8b0dbd3f680051eb078b15b13f680052，asm 366387–366397）。然後呼叫 `0x4e3930`（asm 366418，`call` 在 0x50f304）依成員數逐個建立個體。群組建立的呼叫者：0x48af83、0x48b0c1、0x4bc240、0x4d8f4d、0x4da701（asm 186423、186527、252656、290963、293111）。
- [已驗證] 刪除：`0x4e3af0(id,flag)`（`@0xe3af0`：558b6c2408565755e8231b00008bf8a0，asm 305604–305700）：戰鬥中先退出戰鬥；E+4 不為 0 時群組成員數減一並從 G+8 成員向量移除；釋放 M（0x4c59c0／0x46e5a0／0x4c5860）並清 E+0xc；從向量移除 E。
- [推測] 遍歷全部怪物（含非戰鬥）：靜態上 `0x4e8c30`（asm 312472 起）遍歷 `0x683fad` 全部元素，所以向量含全部個體而非只有戰鬥參與者；但「非戰鬥的遊蕩怪」是否也在 0x683fad 內沒有執行期證據。
- [推測] `0x683fb9`／`0x683fbd`（B 類，`D+0x26a` 非 0）與 `0x683fad`／`0x683fb1`（A 類）的語意差異：在 `0x4e3c70`（asm 約 305769–305790）以 `0x5e2890` 查 E 是否在 `0x683fb9`，結果決定 `0x4c61a0` 模式值（1 或 3）與 `0x4c5a00` 旗標，看起來是友善／NPC 與敵對的分流。無實測。
- 候選容器 2（備援）：[推測] 場景物件清單 `[[0x659ab4]+0xb8]`（清單物件 count＝+4、資料指標＝+0xc），每幀由 `0x4a27c0`（`@0xa27c0`：83ec18538b5c242085db555775195368，asm 217557–217690；唯一呼叫者 `0x44f528`，asm 106363）逐一呼叫 `obj` 的虛擬函式 +0x40（= M 的 vtable 0x5ed22c +0x40 → 0x4c2100）。但清單混有其他物件類型，且「M 是否在此清單」[未取得]（`0x4a89a0` 只是模型名稱註冊表，不是此清單，已排除）。

## X1-Q2 世界座標欄位

- [已驗證] 位置 getter `0x4534c0`（`@0x534c0`：8b44240481c100010000568b318bd089，asm 111878–111888，thiscall）：ecx 指向的物件 +0x100 起複製 12 bytes（3 float）到 arg 指標。
- [已驗證] 怪物：`M = *(u32*)(E+0xc)`，呼叫端以 `ecx = M+0x18` 呼叫 0x4534c0（`0x4c4d40`，asm 263290–263316：`add esi,0x18` 後 `call 0x4534c0`），所以怪物位置 float ＝ M+0x118（X）、M+0x11c（Y）、M+0x120（Z）。M 的 vtable 是 0x5ed22c（建構子寫 [M]=0x5ed22c、[M+0x18]=0x5ed218，asm 257385–257386）。
- [已驗證] 隊伍：同一函式 `0x4c4d40`（`@0xc4d40`：83ec1c56578b3d0c9c650085ff8bf175，M 的方法）對隊伍世界物件 `W=[0x659c0c]` 直接以 `ecx=W` 呼叫 0x4534c0（asm 263295、263308–263312），再把兩個 vec3 傳給 `0x4be420`。proxy.c:1090 讀的隊伍座標是 W+0x100/+0x104/+0x108（X/Y/Z）。隊伍與怪物走同一個 getter、同一組欄位（W 與 M+0x18 同類別），單位與軸一致；水平面＝X、Z。
- [已驗證] `0x4be420(P_from, P_to)`（`@0xbe420`：8b442408d9008b4c2404d821d94008d8，asm 在 0x4be420）讀兩個 vec3 的 +0 與 +8（X 與 Z），做 atan2 類的平面角度；因此它讀的是 M+0x118 與 M+0x120（怪物端）。用例：`0x555d60`（asm 464435–464470）、`0x4c4d40`（asm 263316 呼叫處 0x4c4d87）。
- [已驗證] 朝向：`0x453970`（`@0x53970`：d981d4000000c3909090909090909090，`fld [ecx+0xd4]`）ecx＝M+0x18 → M+0xec（float yaw）。與隊伍 yaw（`f32[D+4]`，D＝[0x65a0f8]）是否同零點／同方向：[未取得]（怪物 yaw 與 `mp8_theta` 的零點未對照）。
- [已驗證] 初始位置寫入：E+0x17/+0x1b/+0x1f 是建立時複製的 3 個 float（asm 305483 起）；`0x4e3c70`（asm 約 305743；`@0xe3c70`：83ec0c568b74241485f657751d8b3df4）啟動個體時於 0x4e3d07（`@0xe3d07`：8d46175051e8ef21feff8b15b93f6800）以 `lea eax,[esi+0x17]` 呼叫 `0x4c5f00(M, &E+0x17)`（`@0xc5f00`：83ec188b442420d90056d95c2404d940）把位置設到 M。
- [未取得] E+0x17 是否隨怪物移動同步更新：靜態上未見；建議把 E+0x17 當「出生／邏輯點」，每幀用 M+0x118。
- [未取得] 單位換算（與地圖頁 X、Z 的整數格比例）：與隊伍同欄位，直接沿用隊伍的換算（mappos8.h 的 X/Z）。

## 執行期傾印驗證清單（Q1 仍僅靜態）

- 讀 `u32@0x683fad`、`u32@0x683fb9`：得向量物件；各取 +0（資料指標）與 +8（元素數）。
- 逐元素 E：印 E+0（id）、E+4、E+8（樣板）、E+0xc（M）、E+0x10、E+0x14、E+0x15、E+0x17..0x22。
- 對 M 非 0 的：印 `float M+0x118/0x11c/0x120` 與 `float M+0xec`，並同時印 `W=[0x659c0c]` 的 `+0x100/+0x104/+0x108`。通過條件：怪物在畫面中靠近隊伍時，兩者 X、Z 差距與畫面距離吻合。
- 殺掉一隻後重印，記錄哪個欄位變化；再切換區域，確認向量元素數與 level（0x686a70）同步變化。
- 若 0x683fad／0x683fb9 都是空：改看備援 `[[0x659ab4]+0xb8]`：清單 count＝+4、資料指標＝+0xc，篩 `*(u32*)obj == 0x5ed22c` 的物件。
